# Obby Zoo: обзор проекта

Актуальность: **16 июля 2026**.

Этот документ дает новый рабочий контекст без необходимости читать всю историю чата. Источником истины для поведения всегда остаются сцены, префабы, ScriptableObject-данные и код текущей ветки.

## 1. Продукт

`Obby Zoo` - WebGL-игра про развитие собственного зоопарка с онлайновым лобби и обязательным офлайн-режимом.

Основной игровой цикл:

1. Игрок получает или покупает яйцо на конвейере.
2. Размещает яйцо на своей территории и ждет вылупления.
3. Получает животное с определенными характеристиками и `ElementType`.
4. Животное приносит пассивный доход.
5. Игрок собирает монеты, открывает клетки, улучшает конвейер и получает более дорогие яйца.
6. Коллекция фиксируется в альбоме, а долгосрочная прогрессия продолжается через большого питомца, магазин, награды и социальные механики.

В интерфейсе и локализации используется термин **«животные»**. Названия `Brainrot`, `brainrot` и похожие классы остались в коде как legacy-терминология; массово переименовывать их без отдельной миграционной задачи нельзя.

## 2. Технологии и целевые платформы

- Unity `6000.3.9f1`.
- Universal Render Pipeline `17.3.0`.
- Основная целевая платформа: WebGL.
- Платформенная интеграция: Mirra SDK 5.
- В проекте также есть провайдеры Yandex Games и локальные Dummy/Debug-провайдеры.
- Основной UI: uGUI + TextMesh Pro.
- Серверный проект: `E:/GitFork/zoogame-backend`.
- Unity Bridge MCP расположен в `Tools/unity-bridge` и используется для Play Mode smoke, проверки иерархии и скриншотов.

## 3. Сцены и запуск

Сцены в Build Settings:

1. `Assets/Scenes/LoadingScene.unity` - стартовая сцена.
2. `Assets/Scenes/Evgesha.unity` - основная игровая сцена.
3. `Assets/Scenes/Melomaner.unity` - отключена из билда.

Основной поток запуска:

1. `GameBootstrap` в стартовой сцене создает постоянные менеджеры.
2. Менеджеры регистрируются в статическом фасаде `G`.
3. `GameLoader` открывает игровую сцену.
4. `GameEntryPoint` создает игрока, инвентарь, быстрые слоты, модификаторы дохода, UI и ожидает данные локаций.
5. При недоступном сервере `RemoteBasesApplier` переводит игру в локальный офлайн-режим.
6. Загрузочный экран скрывается только после подготовки локальной базы или истечения безопасного таймаута.

Ключевые файлы:

- `Assets/_Scripts/GameBootstrap.cs`
- `Assets/_Scripts/GameEntryPoint.cs`
- `Assets/Igrodelnya2.0/GameLoader.cs`
- `Assets/Igrodelnya2.0/G.cs`
- `Assets/_Prefabs/Managers/GameLoader.prefab`

## 4. Архитектурные блоки

### Глобальные сервисы

`G` является существующим service locator. Через него доступны сохранения, валюта, реклама, покупки, ввод, локализация, альбом, доход, удача и другие сервисы.

Новые системы не должны создавать второй параллельный набор глобальных синглтонов. Если сервису действительно нужен глобальный жизненный цикл, его следует подключать через текущий bootstrap и очищать ссылку при уничтожении.

### Платформенные провайдеры

Менеджеры работают через абстрактные провайдеры:

- `SaveProvider`
- `AdsProvider`
- `PurchasesProvider`
- `LocalizationProvider`
- `AnalyticsProvider`
- `DeviceProvider`
- `PauseProvider`

Реализации находятся в `Assets/Igrodelnya2.0/Managers/Provider/`. Любая новая платформенная механика должна иметь безопасный локальный fallback и не блокировать офлайн-игру.

### Сохранения

`SaveManager` делегирует хранение активному `SaveProvider` и периодически вызывает сохранение прогресса. Локальное сохранение авторитетно для собственной базы игрока; удаленный snapshot нельзя применять поверх локальной базы.

При добавлении прогрессии требуется проверить:

- новый профиль;
- повторный запуск;
- перезапуск во время незавершенного действия;
- офлайн-запуск;
- вход, выход и переподключение к лобби;
- миграцию старого сохранения без нового поля.

### Основной геймплей

- Яйца: `Assets/_Scripts/Egg.cs`, `Assets/_Scripts/EggInfoUI.cs`.
- Животные: `Assets/_Scripts/Brainrot/`.
- Стихии и визуальные эффекты: `ElementTypeMultiplaer`, `ElementTypeVfx`.
- Поля и клетки: `FieldManager`, `Field`, `FieldCell`, `IncomeCollector`.
- Конвейер: `Assets/_Scripts/Conveyor/`.
- Большой питомец: `Assets/_Scripts/BigPet/`.
- Еда: `Assets/_Scripts/FoodShop/`.
- Инвентарь и быстрый доступ: `Assets/_Scripts/Inventory/`, `InventoryUI`.
- Альбом: `Assets/_Scripts/UI/Album/`.

Баланс в основном хранится в префабах и ScriptableObject-данных. Перед изменением формул нужно проверить активные данные в сцене и префабах, а не только дефолты в C#.

### Онлайн и офлайн

Сетевой слой находится в `Assets/_Scripts/Net/`.

Основные компоненты:

- `ZooBackendClient` - HTTP API.
- `LobbyClient` - лобби, позиции, WebSocket с fallback.
- `RemoteBasesApplier` - владение слотами, локальная и удаленные базы.
- `ZooBaseSnapshotSync` - snapshot базы.
- `RemotePlayerMover` - отображение удаленных игроков.
- `FriendsPanelController`, `GiftInboxUI`, `FriendRequestInboxUI` - социальные механики.

Критический инвариант: отсутствие сервера не должно мешать загрузке дома, строительству, сохранению и основному игровому циклу.

### UI

Основные редактируемые префабы:

- `Assets/_Prefabs/GameCanvas.prefab`
- `Assets/_Prefabs/UI/Album/AlbumScreen.prefab`
- `Assets/Igrodelnya2.0/SpecialShop/SpecialShop.prefab`
- `Assets/Igrodelnya2.0/Roulette/Roulette.prefab`
- `Assets/Igrodelnya2.0/PlaytimeReward/PlaytimeReward/TimeRewardUI.prefab`
- `Assets/_Prefabs/UI/AdsOverlayCanvas.prefab`
- `Assets/_Prefabs/UI/MobileControls.prefab`
- `Assets/_Prefabs/UI/LocalHomeWorldMarker.prefab`

Визуал должен храниться в префабах. Runtime-код может заполнять данные и создавать повторяемые карточки из префаба, но не должен без необходимости перестраивать вручную настроенные размеры, цвета, изображения и иерархию.

Для адаптивных списков используется `AdaptiveGridSpawner` из `Assets/_Scripts/UI/AdaptiveGrid/`. Он поддерживает процентные отступы, фиксированное число колонок, изменение размера контента для ScrollRect и разные точки начала.

### Ввод

- ПК: клавиатура, мышь и горячие клавиши.
- Мобильные устройства: динамический джойстик, свайп камеры и кнопка прыжка.
- Префаб: `Assets/_Prefabs/UI/MobileControls.prefab`.
- Код: `Assets/Igrodelnya2.0/Input/` и `Assets/_Scripts/Player/`.

Мобильный UI должен создаваться только для touch/mobile-провайдера и учитывать `Screen.safeArea`.

### Реклама и магазин

- Реклама: `Assets/Igrodelnya2.0/Managers/AdsManager.cs`.
- Магазин: `Assets/Igrodelnya2.0/SpecialShop/` и `Assets/_Data/SpecialShopPacks/`.
- Эффекты покупок: `ShopEffectsService`, `IncomeModifiersHub`, `PlayerLuckHub`.

Проект поддерживает rewarded и interstitial-рекламу, отключение рекламы, покупки за харду и рекламный fallback на площадках без IAP.

### Локализация

- Основные данные: `Assets/Igrodelnya2.0/Localization/LocalizationData.asset`.
- Runtime: `LocalizationManager`, `LocalizedText`, `LocalizationUtils`.
- Отдельный backlog: `Assets/Igrodelnya2.0/Localization/Reports/Localization_TODO.md`.

Каждая новая пользовательская строка должна иметь RU/EN, fallback и корректный TMP-шрифт с кириллицей.

## 5. Текущее состояние систем удержания

В проекте уже есть отдельные элементы удержания:

- альбом и награды за открытия;
- рулетка;
- награды за время в игре;
- пассивный и офлайн-доход животных;
- магазин бустеров;
- система квестов;
- большой питомец и прогрессия конвейера.

Они пока не собраны в единую понятную воронку нового игрока. `TutorialManager` и `TutorialStep` существуют, но текущая реализация является минимальным каркасом: она хранит только факт завершения и не дает полноценного устойчивого onboarding-сценария.

## 6. Известные риски

1. Нет полноценного обучения и пошагового восстановления после перезапуска.
2. Аналитика умеет отправлять события, но нет единой схемы продуктовой воронки.
3. Механики удержания существуют раздельно и могут конкурировать за внимание игрока.
4. Интервал принудительной рекламы сейчас требует продуктового пересмотра перед тестами удержания.
5. Локализация еще имеет отдельный незакрытый backlog.
6. Онлайн/офлайн, переподключение и старые сохранения требуют регрессионного smoke после изменений прогрессии.
7. В проекте остается runtime-генерация отдельных UI-элементов; новый UI следует делать prefab-first.
8. Старый `TODO_List.md` содержит ценную сетевую историю, но его дата снимка и часть процентов устарели.

## 7. Проверка изменений

Минимальный порядок проверки каждой игровой задачи:

1. Дождаться завершения Unity-компиляции без новых ошибок.
2. Проверить `git diff --check` по измененным текстовым файлам.
3. Запустить Play Mode через Unity Bridge.
4. Пройти затронутый сценарий в Game View.
5. Проверить Console, включая warnings.
6. Проверить минимум `1280x720` и `800x600`; для мобильного UI также портретный и узкий viewport.
7. Для сохранений повторить сценарий после перезапуска.
8. Для сетевых изменений проверить online, simulated offline и reconnect.
9. Остановить Play Mode перед завершением задачи.

Инструкция по Bridge: `Tools/unity-bridge/CODEX_MCP_WORKFLOW.md`.

## 9. Деплой backend

После изменения серверных контрактов клиент и `E:/GitFork/zoogame-backend` должны быть обновлены синхронно. Команды применения на сервере:

```bash
cd /srv/farmgame
git pull
docker compose stop nginx certbot api
docker compose build api
docker compose up -d
```
