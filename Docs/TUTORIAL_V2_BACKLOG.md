## Цель следующей итерации

Перейти от одного линейного сохранённого индекса к набору самостоятельных tutorial-заданий. Каждое задание должно отдельно активироваться, сохраняться, показывать собственный прогресс и завершаться независимо от положения в каталоге.

Это позволит:

- менять порядок заданий без повторного прохождения уже завершённых шагов;
- вставлять новые задания между существующими;
- показывать новое обучение старым игрокам, если они ещё не проходили его `stable_id`;
- давать разным заданиям разные триггеры, подсказки, прогресс и размер награды.

## 1. Отдельное сохранение каждого задания

Нельзя использовать позицию в массиве как источник истины. Для каждого задания нужен неизменяемый `stable_id` и отдельная запись состояния:

- `status`: `unseen`, `available`, `active`, `completed`; старый `skipped` сохраняется только для совместимости ранее записанных save;
- сериализованный прогресс конкретного задания;
- `started_utc`, `updated_utc`, `completed_utc`;
- версия определения задания для миграций;
- при необходимости — флаги выданных наград и выполненных side effects.

Правила совместимости:

- перестановка задания в каталоге не сбрасывает его состояние;
- уже завершённое задание не запускается повторно только из-за изменения текста, порядка или номера версии;
- `stable_id` нельзя переиспользовать для другого смысла;
- переименование делается через явный alias/migration со старого ID;
- новый ID, отсутствующий в сохранении старого игрока, считается новым заданием и проверяет собственный триггер активации;
- повторное прохождение допускается только через отдельную явную политику, а не автоматически при обновлении definition revision.

Нужно мигрировать текущий `TutorialSaveData` в новую модель без потери завершённого V1-прогресса.

Отдельная будущая задача: составить новую таблицу пунктов и явно отметить:

- какие запускаются контекстно при первом открытии механики;
- какие доступны старым игрокам после обновления;
- какие задания являются обязательными prerequisites для следующих.

## 3. Контракт самостоятельного задания

Каждый пункт должен иметь собственную понятную схему:

| Поле | Что требуется описать |
|---|---|
| `stable_id` | Неизменяемый идентификатор сохранения и аналитики. |
| Pack/category | К какому набору обучения относится задание. |
| Activation trigger | Когда задание впервые становится доступным. |
| Prerequisites | Какие задания или игровые факты обязательны до запуска. |
| Start | Что происходит при активации и какой объект фиксируется как контекст. |
| Goal | Одно понятное действие или результат для игрока. |
| Progress | Счётчик, стадия или проверяемый игровой факт. |
| Completion | Однозначное событие завершения, безопасное при повторной доставке сигнала. |
| Hints | Текст, стрелка, подсветка, UI-target, дополнительная подсказка по таймауту. |
| Reward | `1–3` gems и отдельный идемпотентный флаг выдачи. |
| Priority/order | Как выбрать активное задание, если одновременно доступны несколько. |
| Analytics | События старта, прогресса и завершения с размером награды. |

Задания могут использовать разные реализации подсказок. Для одного достаточно текста, другому нужна world-стрелка, третьему — UI-стрелка, пульсация, дополнительное окно или несколько внутренних стадий.

## 4. Новое расположение UI

Панель текущего задания перенести в свободную область справа сверху, симметрично блоку валюты слева.

Требования:

- отдельный редактируемый prefab;
- привязка к safe area;
- отсутствие пересечения с верхними центральными кнопками и мобильными элементами;
- адаптация минимум под `1280x720`, `800x600` и целевые touch viewport;
- компактное состояние не должно перекрывать игровой обзор;
- world/UI-стрелка продолжает работать независимо от раскрытого состояния текста.

Перед реализацией сделать простой mockup раскрытого и свёрнутого состояний и согласовать размеры.

## 5. Награда и отсутствие пропуска

Каждое успешно завершённое задание выдаёт `1–3` gems. Размер задаётся в definition, отображается в панели до выполнения и передаётся в аналитику.

- первые четыре задания дают по `1` gem;
- следующие пять — по `2` gems;
- последние четыре — по `3` gems;
- полный текущий цикл даёт `26` gems.

Skip-действий в UI и runtime нет. Исторический статус `Skipped` остаётся читаемым только ради совместимости уже существующих сохранений и считается terminal без награды.

## 6. Индивидуальные триггеры активации

Каждое задание получает собственный trigger вместо запуска только по соседнему индексу. Trigger может зависеть от:

- завершения prerequisite-задания;
- наличия/открытия игровой механики;
- входа в зону или открытия окна;
- получения предмета, валюты или уровня;
- первого появления подходящей world/UI-цели;
- версии контента или даты обновления;
- комбинации сохранённых игровых фактов.

Триггеры должны быть повторяемыми и side-effect free: их можно проверять после загрузки, reconnect и смены сцены. Если одновременно подходят несколько заданий, выбор делает явная priority/order policy.

## 7. Сворачивание текста задания

Панель должна сворачиваться отдельной кнопкой-стрелкой:

- при сворачивании текстовая часть анимированно уезжает влево под маску;
- компактная кнопка/маркер остаётся доступной для обратного раскрытия;
- активное задание, его прогресс, world/UI-стрелка и completion listeners продолжают работать;
- состояние свёрнутости хранится как UI preference и не меняет tutorial progress;
- новое критичное задание может показать ненавязчивый badge, но не должно самопроизвольно постоянно раскрывать закрытую игроком панель;
- анимация не должна блокировать клики по игровому миру вне фактической области панели.

## Обязательные проверки

- перестановка definitions не запускает завершённые задания повторно;
- вставка нового `stable_id` активирует его у подходящего старого игрока;
- rename migration сохраняет completed/skipped/progress state;
- restart восстанавливает активное задание и его внутренний прогресс;
- повторный completion не выдаёт gems второй раз;
- миграция V1/V2 не раздаёт награды за исторические terminal-задания;
- два одновременно доступных задания выбираются детерминированно;
- раскрытие/сворачивание не сбрасывает прогресс и не отключает стрелку;
- UI проходит desktop и touch safe-area матрицу;
- аналитика использует `stable_id`, а не позицию задания в каталоге.
